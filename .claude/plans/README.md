# `.claude/plans/` — plan-mode artefacts

When Claude enters [Plan mode](https://docs.claude.com/en/docs/claude-code/plan-mode),
it writes a plan file here before executing. Plan files persist after the
session and become valuable architectural documents in their own right.

| (others, if present) | Archive of earlier plans. |

## Why these are worth keeping

- They're the concrete record of what Claude proposed *and what the user agreed to* before any code was written.
- They double as architectural docs — read at the top is the "Context" section, then "Decisions already taken".
- They're the easiest way to onboard the next engineer: hand them the plan file plus the branch and they can reconstruct the reasoning.

## How a plan gets here

1. The user runs `/plan` or invokes Plan mode.
2. Claude proposes a structure, asks the user via MCQ about open decisions.
3. Claude writes the plan to `.claude/plans/<auto-generated-slug>.md`.
4. User approves via `ExitPlanMode`.
5. Execution proceeds in a normal session, referring back to the plan.

The auto-generated slug pattern (`<adjective>-<participle>-<noun>`) is
intentional — plans are durable artefacts, not throwaways.
