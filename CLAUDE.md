# Claude Code Demo — Music Looper Monorepo

A browser-first music looping web app, built as a Claude Code demo for an
engineering team. **Replaces** an earlier blog/social stdlib API (see tag
`pre-rewrite-snapshot`).

The app lets a user record a short loop from the mic, browse and load
royalty-free sample loops, drop them onto a 4×4 pad grid, play pads in
and out, change speed, and apply filter / delay / reverb effects — all in
the browser via the Web Audio API. The backend stores audio blobs in S3
and metadata in DynamoDB. Local-first via DynamoDB Local + LocalStack.

## Top-level commands

- `pnpm install` — install all workspaces
- `pnpm dev` — concurrent web (3000) + api (3001) dev servers
- `pnpm test` — run Vitest across all workspaces
- `pnpm e2e` — Playwright E2E (behavioural)
- `pnpm e2e:visual` — Playwright screenshot comparison suite
- `pnpm e2e:update` — refresh visual snapshots after intentional UI changes
- `pnpm typecheck` / `pnpm lint`
- `pnpm localstack:up` / `pnpm localstack:down` / `pnpm localstack:seed`
- `pnpm infra:validate` — `terraform fmt -check && validate` against `infra/terraform/`

## Conventions (top-level — packages override)

- TypeScript everywhere except `infra/` (Terraform HCL)
- ESM modules, `"type": "module"` in every package.json
- Vitest for unit + component tests; Playwright for E2E and visual regression
- Zod schemas live in `@looper/shared` and are imported by both web & api
- All audio processing runs **in the browser** (no server-side audio)
- All AWS access goes through LocalStack / DynamoDB Local in dev — never hit real AWS in CI

## Project memory

`.claude/memory/MEMORY.md` is the team-shared, committed-to-git memory layer
for this repo. It holds four types of facts: `project` (initiatives,
deadlines), `decision` (technical/architectural rationale), `feedback`
(team conventions specific to this codebase), `reference` (pointers to
external systems — Linear, Grafana, dashboards, runbooks).

Writes are governed by the `project-memory` skill at
`.claude/skills/project-memory/SKILL.md`. Use `/remember <fact>` to save
explicitly. The skill routes personal preferences (style, role, tooling
taste) to user-level memory at `~/.claude/projects/.../memory/` instead.

The skill MUST refuse to save anything already covered by this file,
`.claude/rules/`, `ANATOMY.md`, `docs/wiki/`, or `git log` — memory is
for facts not derivable from code, conventions, or history.
